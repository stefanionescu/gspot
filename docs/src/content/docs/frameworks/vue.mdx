The `vue` configuration lints Vue components with eslint-plugin-vue and eslint-plugin-vuejs-accessibility, and
type-checks them with vue-tsc. Prettier formats `.vue` files, and the [CSS guide](/languages/css/#component-styles)
covers the style blocks of components.

<ChecksTable guide="frameworks/vue" />

## Type check

When the scope uses `typescript`, `vue/vue-tsc` runs in place of `typescript/tsc`, before each push, and checks every
component and TypeScript file with the strict compiler options of the level. A scope without `typescript` runs no type
check of its components.

## ESLint rules

`javascript/eslint` runs the `flat/recommended` presets of eslint-plugin-vue and eslint-plugin-vuejs-accessibility. It also
reports lost reactivity, unused and untyped refs, a button without a `type`, and an unsafe `target="_blank"` link.
`vue/require-default-prop` is off at both levels, so an optional prop needs no default value.

Level `basic` turns off the style, naming, and ordering rules of the eslint-plugin-vue preset. Level `all` runs them, allows
only `<script setup>`, and when the scope uses `typescript`, requires the type form of `defineProps` and `defineEmits`.
