## Detection

gspot selects `expo` in a scope whose `package.json` depends on `expo`. The configuration requires `react-native`, so
the [React Native](/frameworks/react-native/) and [React](/frameworks/react/) rules run too.

## Doctor check

`expo/expo-doctor` runs Expo Doctor at push, once for each scope. It reports each Doctor check that fails, with its
details, on the `package.json` of the scope. Doctor needs network access.

The check reads the installed Expo project. When `expo` is missing from the installed dependencies of the scope, it
stops and asks you to install them. For example, a `react-native` version that differs from the one the Expo SDK
requires fails a Doctor check. Run `npx expo install --check` to install the matching version.

## ESLint rules

`javascript/eslint` adds these rules of eslint-plugin-expo to the JavaScript and TypeScript files of the scope:

- `expo/no-env-var-destructuring` and `expo/no-dynamic-env-var`, which report a destructured or computed read of
  `process.env`.
- `expo/use-dom-exports`, for components that render with the `"use dom"` directive.
- At level `all`: `expo/prefer-box-shadow`.

The app runs on the device, so `gspot/no-client-environment` allows it only environment variables that start with
`EXPO_PUBLIC_`. API routes that end in `+api.js` or `+api.ts`, config files such as `app.config.ts`, and files under a
`scripts` folder run elsewhere, so the rule skips them.
