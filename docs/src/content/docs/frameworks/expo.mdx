The `expo` configuration runs Expo Doctor, and adds the lint rules of eslint-plugin-expo for public environment
variables and DOM components. It needs `react-native`, so the [React Native](/frameworks/react-native/) and
[React](/frameworks/react/) rules also run.

## Doctor check

Before each push, `expo/expo-doctor` runs Expo Doctor and reports each problem that it finds. It needs network access and
the installed dependencies of the project, and it stops when the scope has no installed `expo`.

A Doctor test fails, for example, when the installed `react-native` version differs from the one that the Expo SDK
needs. Run `npx expo install --check` to install the matching version.

## ESLint rules

`javascript/eslint` reports a destructured or computed read of `process.env`, and `expo/use-dom-exports` checks components
that render with the `"use dom"` directive. Level `all` adds `expo/prefer-box-shadow`.

The app runs on the device, so `gspot/no-client-environment` allows the app only the environment variables that start
with `EXPO_PUBLIC_`. API routes that end in `+api.js` or `+api.ts`, config files such as `app.config.ts`, and files
under a `scripts` folder do not run on the device, so the rule skips them.
