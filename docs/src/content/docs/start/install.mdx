## What you need

Git and Node.js 24.15 or newer. The tools that your checks run need these:

| Tools                                                            | What you need                                                                                           |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| npm tools, such as ESLint or markdownlint                        | Node.js and the project's npm, pnpm, Yarn, or Bun package manager. With no declaration, gspot uses npm. |
| Python tools, such as Ruff or yamllint                           | uv; gspot installs its pinned Python version when needed.                                               |
| Program tools, such as ShellCheck, Gitleaks, and typos           | mise, or the exact pinned tools on `PATH`. `gspot doctor` lists missing tools.                          |
| Project commands, such as Jest, Vitest, Next.js, or Swift builds | Your project's runtime, dependencies, and build tools.                                                  |

`gspot init --dry-run` shows which tools your repository needs.

### Operating system limits

Swift checks need the Swift toolchain. SwiftFormat supports macOS and Linux. Xcode checks and XCTest coverage need macOS with Xcode selected by `xcode-select`. Some container checks need a running Docker daemon. Some scans and generators need network access. Each [check page](/reference/checks/) lists its systems and other requirements.

## Choose how to install

Install gspot with the package manager of your repository. A repository without `package.json`, such as a Python or
Swift project, uses mise, which pins gspot in `mise.toml`. The guides show commands as `gspot ...`; start them as the
last column shows.

Then run `gspot init` and `gspot install`, as the [Quickstart](/start/quickstart/) shows. With mise, `--pin` writes exact
Node.js and gspot versions to `mise.toml`. mise requires approval for a new npm package or one with few downloads;
`allow_low_downloads=true` approves gspot.

:::caution
Install `@gspothq/cli` before you run `npx gspot`. npm has no package named `gspot`, so without the install, npx stops with a 404 error.
:::

## Set up a clone

Use the gspot version in `.gspot/version`. `gspot init` stops where `gspot.toml` exists, so run `gspot install` instead.
Install the app dependencies from the committed lockfile first.

<Tabs syncKey="package-manager">
<TabItem label="npm">

```shell
npm ci
npx gspot install
npx gspot check
```

</TabItem>
<TabItem label="pnpm">

```shell
pnpm install --frozen-lockfile
pnpm exec gspot install
pnpm exec gspot check
```

</TabItem>
<TabItem label="Yarn">

```shell
yarn install --immutable
yarn exec gspot install
yarn exec gspot check
```

Yarn Classic installs with `yarn install --frozen-lockfile`.

</TabItem>
<TabItem label="Bun">

```shell
bun install --frozen-lockfile
bunx gspot install
bunx gspot check
```

</TabItem>
<TabItem label="mise">

```shell
mise exec -- gspot install
mise exec -- gspot check
```

</TabItem>
</Tabs>

`gspot install` installs the tools and turns on hooks in this clone.
If it changes a lockfile under `.gspot/`, commit that file.

## Private registries

The npm, pnpm, Yarn, and Bun installs of gspot use the registry settings of your repository and your environment. uv
reads Python package indexes from `uv.toml` or `[tool.uv]` in `pyproject.toml`.

Keep credentials in environment variables or your user settings, never in `gspot.toml` or a lockfile.
