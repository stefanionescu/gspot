gspot picks linters and formatters for the languages and frameworks in your repository, and pins each one to one
version. Git hooks run them before each commit and push. gspot also writes `AGENTS.md` and rule files that tell coding
agents how to write code that passes.

gspot has configurations for JavaScript, TypeScript, Python, Swift, shell scripts, CSS, HTML, SQL, and Markdown. The
[configuration reference](/reference/configurations/) lists them, with the frameworks and tools that gspot checks.
Files in other languages, such as Go, Rust, or Java, get only the checks that run in every repository, such as the
secret scan and the spelling check.

You need Git and {`Node.js ${runtimeMinimums.node} or newer`}.

## Try gspot on a copy

Run this at the root of a Git repository:

```shell
npx @gspothq/cli scan
```

`gspot scan` copies your tracked files into `.gspot-copies/`, sets gspot up in the copy, and runs every check with no
fixes. Then it deletes the copy. Your repository does not change, but mise installs the tools for your whole machine.

The report counts the findings by category and shows three of each. It also prints the plan of `gspot init`: the files
it writes and deletes, the settings it carries over, and the commands that stop working. Add `--markdown` for a report
to paste into a pull request, or `--json` for every finding.

The scan runs the tools of your project and loads your Prettier config. Run it only on code you trust.

## Set up gspot

Run these commands at the root of your repository:

1. The first command adds gspot to your project at one exact version. With mise, the line before it pins Node.js in
   `mise.toml`.
2. `gspot init` prints its plan and carries it out without asking. It writes `gspot.toml` and the generated files: the
   config files of the tools, `AGENTS.md`, the rules for coding agents, and the Git hooks. It deletes the tool configs
   that it replaces; Git keeps their history. Then it installs the pinned tools and turns on the Git hooks.

The pre-commit hook now checks the staged files, and the pre-push hook checks the pushed files. CI stays off until you
[turn it on](/use/ci/#turn-ci-on).

gspot starts at level `basic`. For stricter checks, run `gspot init --level all`. [Levels](/start/concepts/#levels)
compares the two.

## Clean up the first findings

Format the files that the checks now cover:

```shell
gspot check --fix
```

To accept the findings that remain and fix them later, record a [baseline](/use/baseline/). The checks then fail only
on new findings:

```shell
gspot baseline
```

Run `gspot check --fix` first. A baseline leaves out the findings that the fixers can fix, so they keep failing until
you run it.

Commit `gspot.toml`, `gspot.baseline.json`, and the generated files. [Files and caches](/reference/generated-files/)
lists them.
