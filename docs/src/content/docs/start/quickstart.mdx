Set up gspot yourself, or give one prompt to your coding agent.

## Set up gspot yourself

Run these commands in the root of your repository.

<Tabs syncKey="package-manager">
    {SETUP_COMMANDS.map(({ label, lines }) => (
        <TabItem label={label}>
            <Code code={lines.join('\n')} lang="shell" />
        </TabItem>
    ))}
</Tabs>

1. The first command adds gspot to the project, pinned to one version.
2. `gspot init` shows a plan. When you accept it, gspot writes `gspot.toml`, the config files, `AGENTS.md` and the
   rules, and the Git hooks, and deletes the config files it replaces. When the `origin` remote points to GitHub or
   GitLab, it also writes the CI workflow.
   [Read the plan](/start/migrate/#read-the-plan) first.
3. `gspot install` installs the pinned tools and turns on the hooks. From then on, every commit runs the checks.

gspot starts at level `basic`. For stricter checks from the start, run `gspot init --level all`.
[Levels](/start/concepts/#levels) says what each level checks.

## Set up gspot with your coding agent

Paste this prompt into Claude Code, Codex, Cursor, or another coding agent that can run commands.

<Code code={AGENT_PROMPT} lang="text" />

The agent then:

1. Adds `@gspothq/cli` with the package manager of your repository, or pins it with mise.
2. Asks which [level](/start/concepts/#levels) you want, runs `gspot init --dry-run` at that level, and shows you
   the plan. It writes the plan only after you agree.
3. Runs `gspot install` and `gspot check`, and shows you the result.
4. Reads `AGENTS.md` and the agent rules before it writes more code.

## After you install

Commit `gspot.toml` and the files that gspot wrote; [Generated files](/reference/generated-files/) lists them. Then
commit as usual. The pre-commit hook checks the staged files and stops the commit when a check fails. Run
`gspot check` to check every file, including work that you did not commit.
