---
title: Upgrade gspot
description: Install a new gspot version and update the generated files.
---

import { Tabs, TabItem, Code } from '@astrojs/starlight/components';
import { setup } from '#docs/reference/setup.ts';

Commit first, so you can go back. Pick a [release](https://github.com/stefanionescu/gspot/releases), such as `1.2.0`,
and put it in place of `<version>` below.

<Tabs syncKey="package-manager">
    {setup.map(({ label, start, add }) => (
        <TabItem label={label}>
            <Code
                lang="shell"
                code={[`${add}@<version>`, `${start} apply`, `${start} install`, `${start} check`].join('\n')}
            />
        </TabItem>
    ))}
</Tabs>

`gspot apply` updates the generated files. If it refuses a key of `gspot.toml`, the message names the close keys. Edit
`gspot.toml`, then run `gspot apply` again.

When `gspot apply` succeeds, review the diff and fix any findings. Then commit the generated files that changed, in
`.gspot/` and outside it, and either `package.json` with its lockfile or `mise.toml`, together. Commit `gspot.toml` too
if you changed it to fix findings. Every other clone then runs `gspot install`. See [Set up a
clone](/start/install/#set-up-a-clone).

If `gspot apply` says that it did not overwrite some files, gspot did not write them. Move each one aside, then run
`gspot apply` again.

To return to an older gspot, check out the commit before the upgrade.

Upgrades can leave older global tool versions and download caches outside the repository. After verifying the new
version, follow [Reclaim shared disk space](/start/footprint/#reclaim-shared-disk-space) to preview
`mise prune` and run `uv cache prune` when you want to reclaim that space.
