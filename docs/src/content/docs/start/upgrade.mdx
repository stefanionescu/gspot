Commit first, so you can go back. Read the [release notes](https://github.com/stefanionescu/gspot/releases), pick a
release, such as `1.2.0`, and put it in place of `<version>` below.

`gspot apply` writes the new version to `.gspot/version` and updates the generated files. Review the diff and fix any findings. Then commit the generated files that changed, in `.gspot/` and outside it,
and either `package.json` with its lockfile or `mise.toml`, together. Commit `gspot.toml` too if you changed it to fix
findings. Every other clone then runs `gspot install`. See
[Set up a clone](/start/install/#set-up-a-clone).

If `gspot apply` names a JSON file it did not overwrite, delete that file and run `gspot apply` again. A JSON file has
no header that marks it as generated, so gspot 0.1 kept that mark in a log that newer versions do not read.
