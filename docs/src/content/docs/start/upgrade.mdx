import { Tabs, TabItem, Code } from '@astrojs/starlight/components';

Commit first, so you can go back. Pick a [release](https://github.com/stefanionescu/gspot/releases), such as `1.2.0`,
and put it in place of `<version>` below.

<TabItem label="mise">

```shell
mise use --pin --tool-option allow_low_downloads=true npm:@gspothq/cli@<version>
mise exec -- gspot apply
mise exec -- gspot install
mise exec -- gspot check
```

</TabItem>

</Tabs>

`gspot apply` writes the new version to `.gspot/version` and updates the generated
files. If it refuses a key of `gspot.toml`, the message names the close keys. Edit `gspot.toml`, then run `gspot apply`
again.

When `gspot apply` succeeds, review the diff and fix any findings. Then commit the generated files that changed, in `.gspot/` and outside it,
and either `package.json` with its lockfile or `mise.toml`, together. Commit `gspot.toml` too if you changed it to fix
findings. Every other clone then runs `gspot install`. See
[Set up a clone](/start/install/#set-up-a-clone).

If `gspot apply` reports files it did not overwrite, move each one aside. Then run `gspot apply` again.
