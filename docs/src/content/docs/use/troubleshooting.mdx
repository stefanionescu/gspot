Start with `gspot doctor`. It lists missing tools, problems with the Git hooks, and configurations that your repository
needs. `gspot check --only gspot/generated-files --verbose` lists each generated file that does not match `gspot.toml`,
with its diff. When you [report a problem](https://github.com/stefanionescu/gspot/issues), include the output, the
check ID, and a command that shows the problem. Leave out credentials.

## A command reports an error in `gspot.toml`

Fix the value or table that the error names, and run the command again. A setting that makes a check less strict needs
a reason next to its value.

## A check reports `missing`

Run `gspot install`. With mise, it installs the tools that mise provides. Without mise, install the tools that
`gspot doctor` lists yourself, as [What you need](/start/install/#what-you-need) describes. While a tool is missing,
the run cannot finish and exits with code 2. In a Git hook, that also stops the commit.

To create the tool lockfiles again, delete the lockfiles in `.gspot/`, run `gspot install`, and commit the new
lockfiles.

## `gspot install` or `gspot scan` hits the GitHub rate limit

mise looks up each pinned tool on GitHub. Without a token, GitHub allows 60 lookups an hour, and gspot prints:

```text
GitHub limits the release lookups of mise without a token. Set GITHUB_TOKEN to a GitHub token, then run gspot install again.
```

Set `GITHUB_TOKEN` to a GitHub token that can read public releases, then run the command again. `gspot scan` stops with
exit code 2 when it hits the same limit. In CI, the job that gspot writes passes its own token.
[mise: If something does not work](https://mise.jdx.dev/getting-started.html#if-something-doesn-t-work) has more help.

## A generated file has local edits

`gspot install` overwrites the local edits in a generated file. Move each change into `gspot.toml` first, as
[Do not edit generated files](/reference/generated-files/#do-not-edit-generated-files) describes.

## A check runs slowly

Run `gspot check --verbose`. Each passed check then shows its number of files, its time, and the command that it ran.
To time one check alone, run `gspot check --only <check>`. A tool command that runs longer than `tool_timeout_seconds`,
600 seconds by default, stops with an error.

## `npm exec` cannot find gspot

`gspot init` adds gspot to `package.json`, but installs nothing. Run the install command of your package manager, then
`gspot install`. Each new clone or Git worktree needs its own install, because it cannot use the packages of another
worktree.

## A hook cannot find npm, pnpm, Yarn, Bun, or mise

The hook did not find the program that starts gspot, so it stopped the commit. The message names the program and the
`PATH` that the Git client gave the hook:

<Code code={runners.npm.missing.replace('$PATH', '/usr/bin:/bin')} lang="text" />

A Git client in an editor can get a different `PATH` from your terminal. Start the client from a terminal, or add the
folder of the program to the `PATH` of the client, then restart the client. If the program is not installed, install
the package manager or mise first.

When the hook says that gspot is not installed in the worktree, run the install command that the hook prints, in that
worktree. Then run `gspot install`. With mise, run `mise install` in that worktree, then `gspot install`.
