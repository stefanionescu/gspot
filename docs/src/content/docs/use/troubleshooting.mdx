Start with `gspot doctor`. It lists missing tools, hook problems, and configurations that the repository needs.
`gspot check --only gspot/generated-files --verbose` shows the generated files that differ from `gspot.toml`, with
their diffs. When you [report a problem](https://github.com/stefanionescu/gspot/issues), include the output, the check
ID, and the command that reproduces it. Leave out credentials.

## A command reports an error in `gspot.toml`

Fix the value or table that the error names, and run the command again. A setting that loosens a check needs a reason
beside its value.

## A check reports `missing`

Run `gspot install`. It installs the tools that mise provides; without mise, install the tools that `gspot doctor`
lists. See [What you need](/start/install/#what-you-need). A missing tool makes the run incomplete, with exit code 2,
which also stops a commit in the hook.

To make new tool lockfiles, delete the lockfiles in `.gspot/`, run `gspot install`, and commit them.

## `gspot install` or `gspot scan` hits the GitHub rate limit

mise looks up each pinned tool on GitHub. Without a token, GitHub allows 60 lookups an hour, and gspot prints:

```text
GitHub limits the release lookups of mise without a token. Set GITHUB_TOKEN to a GitHub token, then run gspot install again.
```

Set `GITHUB_TOKEN` to a GitHub token that can read public releases, then run the command again. `gspot scan` stops with
exit code 2 on the same limit. In CI, the generated job passes its own token. See
[mise: If something does not work](https://mise.jdx.dev/getting-started.html#if-something-doesn-t-work).

## A generated file has local edits

`gspot install` replaces the edits; see
[Do not edit generated files](/reference/generated-files/#do-not-edit-generated-files).

## A check runs slowly

Run `gspot check --verbose`. Each passed check then shows its number of files, its time, and the command that it ran.
Run one check alone with `gspot check --only <check>`. A tool command that runs longer than `tool_timeout_seconds`
stops with an error; the setting defaults to 600.

## `npm exec` cannot find gspot

`gspot init` adds gspot to `package.json`, but installs nothing. Run the install of your package manager, then
`gspot install`. A new clone or Git worktree needs its own install: the packages of another worktree do not count.

## A hook cannot find npm, pnpm, Yarn, Bun, or mise

The hook did not find the program that starts gspot, and stopped the commit. The message names the program and the
`PATH` that the Git client gave the hook:

<Code code={runners.npm.missing.replace('$PATH', '/usr/bin:/bin')} lang="text" />

A Git client in an editor can get another `PATH` than your shell. Start the client from a terminal, or give it a
`PATH` that holds the program, then restart it. If the program is not installed, install the package manager or mise
first.

When the hook says that gspot is not installed in this worktree, run the install command that it prints in that
worktree, then `gspot install`. With mise, run `mise install` there, then `gspot install`.
