## Vulnerabilities

Before each push that changes a lockfile, `dependencies/osv-scanner` reads your lockfiles and reports each package with a
known vulnerability. A finding points at the line of the package in its lockfile, and names the versions that fix the
vulnerability when the advisory lists them. Each run sends the names and versions of the locked packages to the Open Source Vulnerabilities (OSV)
service. To keep a package that has an advisory, [ignore the advisory](/use/ignore/#ignore-a-dependency-advisory) with a
reason.

The check does not read the lockfiles in `.gspot/`. To get fixes for the tools of gspot, upgrade gspot.

A push that changes no lockfile skips this check, so a new advisory on a version you already locked stays unreported until
a push changes a lockfile. gspot adds no scheduled job to your CI. To scan on a schedule, add a workflow of your own next
to `.github/workflows/gspot.yml`. Copy its steps up to and including `Install gspot tools`, set `on.schedule`, and end
with this step, which reads every lockfile:

```yaml
- run: gspot check --only dependencies/osv-scanner
```

## Registry hosts

By default, lockfile downloads may come from `registry.npmjs.org` and `registry.yarnpkg.com`. To allow another host, list
every host, because `gspot set` replaces the whole list:

```shell
gspot set dependencies.allowed_registries registry.npmjs.org registry.yarnpkg.com npm.example.com --reason "<why>"
```

Downloads must still use HTTPS. A host allowed in a scope counts for that folder and the folders inside it.
