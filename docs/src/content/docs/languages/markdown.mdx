gspot lints Markdown files, and Markdown with JSX (MDX) files, with markdownlint. Its own check parses the code blocks
inside them. Prettier formats the files through the `format` configuration, which is on in every repository.
The `markdown` and `mkdocs` configurations run these checks:

The `prose` and `spelling` configurations check the words of the same files.

## What gspot detects

gspot turns on `markdown` in a scope that has a file ending in `.md` or `.mdx`. It turns on `mkdocs` when an
`mkdocs.yml` or `mkdocs.yaml` file uses the `admonition`, `pymdownx.details`, or `pymdownx.tabbed` extension.

## Lint rules

gspot starts from the Prettier style of markdownlint, which turns off the rules that Prettier already handles, such as
line length and list indentation. Then gspot changes these rules:

| Rule    | Setting                                                                                             |
| ------- | --------------------------------------------------------------------------------------------------- |
| `MD018` | On: a heading needs a space after its `#`.                                                          |
| `MD020` | On: a closed heading needs spaces inside its `#` marks.                                             |
| `MD024` | Two headings with the same text get a finding only when they share a parent heading.                |
| `MD026` | A heading may not end in `.`, `,`, `;`, `:`, `!`, or `?`, or their full-width forms.                |
| `MD033` | Off: inline HTML is allowed.                                                                        |
| `MD046` | Code blocks must be fenced, not indented.                                                           |
| `MD059` | Link text such as `here`, `this page`, `read more`, `click here`, `link`, or `docs` gets a finding. |

Level `all` adds `MD041`, which asks for a top-level heading on the first line, and `MD025`, which allows one
top-level heading per file. For `MD025`, gspot sets `front_matter_title` to an empty string, so a `title` in the front
matter does not count as a top-level heading.

markdownlint skips the front matter of a file. In an `.mdx` file, the rules start after the leading `import` and
`export` lines.

## Code blocks

`markdown/fences` parses the code blocks of these languages: JSON, JSON with comments (JSONC), TOML, YAML, Bash,
JavaScript, JSX, TypeScript, TSX, and Python. It reports each syntax error at its line:

```text
failed   markdown/fences  2 findings
  README.md:10  syntax  Fix this code example: JSON syntax error: property name expected.
  README.md:14  syntax  Fix this code example: Syntax error.
```

The check accepts these shortcuts, which documentation often uses:

- The check skips a block with a line of only `...`.
- `(...)` reads as an empty argument list.
- A placeholder such as `<name>` in a Bash block reads as a word.
- A JavaScript or TypeScript block may hold an expression or object members instead of a whole program, and a
  TypeScript block may hold a type. A Python block may hold an expression.

Label a block `text` when it holds no code.

## Settings

`tools.markdownlint.rules` sets the options of a rule that your level runs. Each entry takes an option table:

```shell
gspot set tools.markdownlint.rules '{ MD024 = { siblings_only = false } }'
```

gspot rejects options for a rule that your level does not run, and names the level that runs it. gspot does not run
`MD013`, the line length rule, at any level. To turn a rule off, ignore it with a reason:

```shell
gspot ignore markdown/markdownlint --rule MD046 --reason "The changelog quotes indented code from old releases."
```

gspot writes a `.markdownlint.jsonc` that loads its rule file, so that an editor reads the same rules.
[Editors](/use/editors/#how-editors-find-the-generated-config-files) lists the other pointer files.

## Admonitions and content tabs

In MkDocs, an admonition, a details block, or a content tab indents its body by four spaces. markdownlint reads
such a body as an indented code block, and the link references inside it as unused. The `mkdocs` configuration turns
off `MD046` and `MD053`, so these blocks get no findings.
