`javascript/eslint` runs rules from ESLint, unicorn, security, import-x, regexp, n, jsdoc, and the gspot plugin, and
framework configurations add their own. Level `all` adds sorted imports, size limits, and no default exports.
`gspot explain javascript/eslint <rule>` explains one rule.

A `package.json` alone turns on `javascript`, and declaration files alone do not turn on `typescript`.

## JavaScript runtimes

ESLint gives each file one runtime: the set of global names, such as `window` or `process`, that the file can use
without an import.

| Files                                                                                | Runtime                                                   |
| ------------------------------------------------------------------------------------ | --------------------------------------------------------- |
| Ordinary modules and build scripts                                                   | Node.js built-ins                                         |
| `.cjs` and `.cts` files, and the `.js` files of a package without `"type": "module"` | Node.js built-ins and CommonJS globals                    |
| React, Vue, and Svelte application sources                                           | Browser globals                                           |
| React Native sources                                                                 | Native globals                                            |
| Next.js sources                                                                      | Node.js built-ins, because server components can use them |

To give some files another runtime, add a `[[tools.eslint.override]]` record, with paths from the root folder of the
repository. When two records match a file, the later record wins.

```toml title="gspot.toml"
[[tools.eslint.override]]
paths = ["src/client/**"]
runtime = "browser"

[[tools.eslint.override]]
paths = ["src/workers/**"]
runtime = "worker"

[[tools.eslint.override]]
paths = ["src/serviceworker.js"]
runtime = "serviceworker"
```

Use a name from the [globals package](https://github.com/sindresorhus/globals), such as `browser`, `node`, `worker`, or
`serviceworker`. With an unknown name, `javascript/eslint` stops and lists the valid names. For server code inside a
browser or React Native project, set the runtime `node`. Browser and native files get no Node.js lint rules.

## TypeScript compiler

- With your own `tsconfig.json`, gspot keeps your compiler options and adds the strict options that the level needs.
- Without one, gspot writes a TypeScript project for the source files of each scope.
- gspot uses the TypeScript compiler of your project for the type checks and for the lint rules that read types. When
  your project has no compiler, gspot uses the one that `gspot install` pins.

`javascript/tsc` checks the JSDoc types of JavaScript files. It reads your `jsconfig.json`, or your `tsconfig.json` when
no `jsconfig.json` exists. With neither file, gspot writes a jsconfig for the check.

## Import extensions

`javascript.import_extension` sets how a relative import of a code file ends: `js`, `ts`, or `extensionless`. `gspot init`
picks the value from the project:

| Project                                                                                                             | Style           |
| ------------------------------------------------------------------------------------------------------------------- | --------------- |
| The tsconfig sets `allowImportingTsExtensions` or `rewriteRelativeImportExtensions`                                 | `ts`            |
| The tsconfig uses `NodeNext`                                                                                        | `js`            |
| The tsconfig uses `Bundler`, the project depends on a bundler such as Vite, or it uses Astro, React, Svelte, or Vue | `extensionless` |
| Any other project                                                                                                   | `js`            |

With Astro, React, Svelte, or Vue, `ts` applies only when the code already imports `.ts` files. An import of a style
sheet or a JSON file keeps its extension. `.mjs` files, `.cjs` files, and Node.js scripts with a shebang always import
the full file name, because Node.js needs it. In these files, an import alias such as `#lib/log` must come from the
`imports` field of `package.json`, because Node.js does not read tsconfig paths.

For modules that a host application provides at run time, follow
[Modules that the host provides](/configure/import-rules/#modules-that-the-host-provides).
