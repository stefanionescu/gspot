gspot lints SQL files with SQLFluff, in the dialect of your database. gspot installs SQLFluff itself, so your project
needs no Python packages. The `sql` configuration runs these checks:

## When gspot turns it on

gspot turns on `sql` in a scope that has a file ending in `.sql`, `.pgsql`, or `.psql`. The
[`postgres` configuration](/reference/configurations/postgres/), which checks Postgres migrations, also turns on `sql`
and sets `sql.dialect` to `postgres`.

## Dialect

`sql.dialect` names the SQL dialect that SQLFluff parses: the form of SQL of one database, such as `postgres`, `mysql`,
or `sqlite`. Its default is `ansi`, so set it to the dialect of your database:

```shell
gspot set sql.dialect postgres
```

SQLFluff reads each file as plain SQL. It does not expand Jinja or other templates.

## Style

gspot sets the letter case of each kind of word:

| Words       | Case       |
| ----------- | ---------- |
| Keywords    | Upper case |
| Identifiers | Lower case |
| Functions   | Lower case |
| Literals    | Upper case |
| Types       | Upper case |

For example, `select id from user_accounts;` gets a `CP01` finding for each lowercase keyword.

SQLFluff takes its line length from `format.print_width`, and its indent from the `format` settings of SQL files. When
the rest of your repository uses another indent, `gspot init` writes a `[[format.override]]` record that indents SQL
files by four spaces, and you change the SQL indent in that record.

## Levels

At level `basic`, gspot turns off six SQLFluff rules about joins, casts, subqueries, and `LIMIT`: `AM05`, `AM09`,
`CV11`, `ST05`, `ST07`, and `ST09`. Level `all` runs them.

## Old settings and ignores

gspot reads only the SQLFluff settings that it writes. `gspot init` deletes `.sqlfluff` and `.sqlfluffignore`, and
`git show <commit>:.sqlfluff` prints the old file. Set the dialect with `sql.dialect` and the indent with `format`.
gspot has no setting for other SQLFluff options. A SQLFluff table in `pyproject.toml`, `setup.cfg`, or `tox.ini` stays,
and `gspot/conflicting-configs` reports it until you delete it.

To turn one rule off, ignore it with a reason:

```shell
gspot ignore sql/sqlfluff --rule AM04 --reason "The reporting views mirror every column of their table."
```

To allow one statement, add a `noqa` comment with a reason, such as
`SELECT * FROM orders -- noqa: AM04 -- reason: the view mirrors every column`.
