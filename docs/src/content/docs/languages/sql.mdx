gspot lints SQL files with SQLFluff, in the dialect of your database. `gspot check --fix` rewrites what SQLFluff can
fix, such as the case of keywords and the layout of a statement. The `sql` configuration runs these checks:

<ChecksTable guide="languages/sql" />

## What gspot detects

gspot turns on `sql` in a scope that has a file ending in `.sql`, `.pgsql`, or `.psql`. The
[`postgres` configuration](/reference/configurations/postgres/) also turns on `sql`. It checks Postgres migrations, and
sets the SQLFluff dialect to `postgres`.

`gspot install` installs SQLFluff into `.gspot/.venv`, separate from the Python environment of your project.

## Dialect

`sql.dialect` names the SQL dialect that SQLFluff parses: the form of SQL of one database, such as `postgres`,
`mysql`, or `sqlite`. Its default is `ansi`. Set it to the dialect of your database:

```shell
gspot set sql.dialect postgres
```

SQLFluff reads each file as plain SQL. It does not expand Jinja or other templates.

## Style

gspot sets the letter case of each kind of word:

| Words       | Case       |
| ----------- | ---------- |
| Keywords    | Upper case |
| Identifiers | Lower case |
| Functions   | Lower case |
| Literals    | Upper case |
| Types       | Upper case |

For example, `select id from user_accounts;` gets a `CP01` finding for each lowercase keyword. `gspot check --fix`
rewrites it as `SELECT id FROM user_accounts;`.

SQLFluff takes its line length from `format.print_width`, and its indent from the `format` settings of SQL files. When
the rest of the repository uses another indent, `gspot init` writes a `[[format.override]]` record that indents SQL
files by four spaces. To change the SQL indent, change that record.

## Levels

At level `basic`, gspot turns off six SQLFluff rules about joins, casts, subqueries, and `LIMIT`: `AM05`, `AM09`,
`CV11`, `ST05`, `ST07`, and `ST09`. Level `all` runs them.

## Exemptions and ignores

SQLFluff runs with `--ignore-local-config`, so it reads only the config file that gspot writes. `gspot init` deletes a
`.sqlfluff` or `.sqlfluffignore` file, and Git keeps its committed version. `gspot init` leaves a SQLFluff table in
`pyproject.toml`, `setup.cfg`, or `tox.ini` in place. `gspot/conflicting-configs` reports that table until you delete
it, as [Read the plan](/start/migrate/#read-the-plan) describes.

To turn one rule off, ignore it with a reason:

```shell
gspot ignore sql/sqlfluff --rule AM04 --reason "The reporting views mirror every column of their table."
```

To allow one statement, add a `noqa` comment with a reason, such as
`SELECT * FROM orders -- noqa: AM04 -- reason: the view mirrors every column`.
