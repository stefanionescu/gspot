gspot checks shell scripts for mistakes with ShellCheck, and for layout with shfmt. It checks the syntax of Zsh scripts
with `zsh -n`. Its own checks report unsafe commands, scripts without strict mode, and functions that nothing calls.

## What gspot detects

gspot turns on `bash` in a scope that has a file ending in `.sh`, `.bash`, `.zsh`, or `.bats`. A file without one of
these extensions also counts when its shebang, the `#!` line at the top, names a shell: `bash`, `sh`, `zsh`, `dash`,
`ksh`, or `bats`. For example, an executable script that starts with `#!/usr/bin/env bash` turns on `bash`, whatever
its name.

Each tool reads the scripts of its own shell:

| Scripts                      | Tools                                 |
| ---------------------------- | ------------------------------------- |
| Bash, `sh`, `dash`, and bats | ShellCheck and shfmt                  |
| Zsh                          | `zsh -n`, through `bash/zsh-syntax`   |
| Every shell script           | The built-in checks, such as `safety` |

ShellCheck reads a script without a shebang as Bash. `bash/zsh-syntax` runs the `zsh` that your system has.
`gspot install` does not install Zsh, so install it yourself when your repository has Zsh scripts.

## Levels

At level `basic`, ShellCheck runs its default checks. `bash/safety` reports commands that kill processes by name, such
as `killall`, and recursive deletes. It also reports the forms that the rule file `BASH.md` forbids, such as `eval` and
`curl` without `--fail`.

At level `all`, gspot turns on these optional ShellCheck checks: `add-default-case`, `avoid-negated-conditions`,
`avoid-nullary-conditions`, `check-extra-masked-returns`, `check-set-e-suppressed`, `check-unassigned-uppercase`,
`deprecate-which`, `quote-safe-variables`, `require-double-brackets`, `require-variable-braces`, and
`useless-use-of-cat`. `bash/safety` then also reports the `function` keyword, `&>`, `echo`, a failure discarded with
`true`, `set -x`, `seq` loops, and `IFS` set at the top level of a script. Level `all` also adds the checks for script
layout, doc comments, unused functions, function size, and inline Python or Node code.

For example, a script that pipes a download into a shell gets two findings at both levels:

```bash title="example"
curl https://example.com/install.sh | bash
```

```text
failed   bash/safety  2 findings
  scripts/deploy.sh:14  curl-fail  Pass `--fail`, so that an HTTP error stops the script.
  scripts/deploy.sh:14  curl-pipe-shell  Nobody can read a script that runs as it downloads. Download it to a file, check it, then run it.
```

## Settings

shfmt reads its layout options from `.editorconfig`, which gspot writes from the `format` settings. When most lines of
your `.sh` and `.bash` files use another indent, `gspot init` writes a `[[format.override]]` record for them, and you
change the indent in that record. The same `.editorconfig` turns on the shfmt options `switch_case_indent` and `simplify`.

`bash/function-size` reads four limits: `limits.bash.max_function_lines`, `max_function_branches`,
`max_block_nesting`, and `max_function_assignments`. By default, a shell function may have 40 lines of code. To raise a
limit, give a reason:

```shell
gspot set limits.bash.max_function_lines 60 --reason "The deploy script keeps its steps in one function."
```

To turn off one ShellCheck code, ignore it by its code with a reason:

```shell
gspot ignore bash/shellcheck --rule SC2086 --reason "The build flags split into words on purpose."
```

To allow one line only, add a ShellCheck comment with a reason, such as
`# shellcheck disable=SC2086 # reason: the word splitting is wanted here`.

## Rules gspot turns off

- In `.bats` files, ShellCheck skips SC2030, SC2031, SC2034, and SC2218. These codes do not fit bats: it runs each test
  in a subshell, defines tests below the helpers they call, and reads variables from loaded helpers.
- ShellCheck finds the file of a `source` command from the folder of the script, and reads that file.
- The naming checks accept the variables that the shell defines, such as `IFS`, `OPTARG`, `BASH_SOURCE`, and
  `PIPESTATUS`.
- A name that starts with an underscore marks a private function or variable. The naming checks ignore the underscore.
- `bash/safety` accepts `rm -r` on a path from `mktemp` inside a trap.

## Rules for coding agents

The `bash` configuration writes the rule files `BASH.md`, `OPERATIONS.md`, and `SAFETY.md` for coding agents. The
[`bash` configuration reference](/reference/configurations/bash/) lists every rule of each check.
