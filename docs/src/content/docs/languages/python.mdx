## Before you start

In a repository without a `package.json`, install gspot with mise, as the [Quickstart](/start/quickstart/) shows.
Manage your project with uv. basedpyright and pytest read the `.venv` of the project, so create it before you run
`gspot init`. In a new clone, create it before you run `gspot install`:

```shell
uv sync
```

`gspot init` writes the basedpyright settings for the `.venv` only when `uv.lock` exists. If you run `uv sync` after
init, run `gspot install` to write those settings.

gspot runs its Python tools with a Python version that it pins. Your `.python-version` file and your `UV_PYTHON`
variable change only the Python of your project.

## Quotes

Ruff formats Python strings with double quotes. To keep single quotes in Python, set `format.quotes`. This setting
applies to every language:

```shell
gspot set format.quotes single
```

## Modules from outside the project

List the modules that a host application provides in `python.externals`, as
[Modules that the host provides](/configure/import-rules/#modules-that-the-host-provides) shows.

`python.import_folders` adds folders inside the scope where basedpyright and the import rules check look for imported
modules. When the host application is outside the repository, add a `.pth` file that names the host folder to the
`site-packages` folder of `.venv`. Python and basedpyright read the folder paths in a `.pth` file, as they do for an
editable install:

```shell title="example"
echo "<host-folder>" > .venv/lib/<python-folder>/site-packages/host.pth
```

`<host-folder>` is the absolute path of the host application, and `<python-folder>` is the Python folder of the
environment, such as `python3.12`.

## Unused code and long functions

At level `all`, `python/vulture` finds functions, classes, and attributes that no file of the scope uses, and code that
never runs. It cannot tell the public API of a library from unused code, so level `basic` does not run it. A framework
can call a definition by its name, which vulture does not see. In that case, ignore the file that holds the definition,
with a reason:

```shell
gspot ignore python/vulture --paths nodes.py --reason "ComfyUI calls the execute method of each node."
```

`python/function-size` checks each function against `limits.max_function_lines`.

## Docstring style

pydoclint takes its docstring style from the first source that sets one:

1. A `[tool.pydoclint]` style in `pyproject.toml`.
2. The pydocstyle convention in the Ruff options of the project.
3. `python.docstring_convention`, when it equals `google` or `numpy`.
4. Google or NumPy sections that gspot finds in your docstrings.

Otherwise, pydoclint uses its default.
