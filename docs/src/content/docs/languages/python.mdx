## Before you start

In a repository without a `package.json`, install gspot with mise, as the [Quickstart](/start/quickstart/) shows.
basedpyright and pytest read the `.venv` of the project, so manage the project with uv, and run `uv sync` before
`gspot init` and again after each new clone.

If you add `uv.lock` after `gspot init`, run `gspot install` so that basedpyright finds `.venv`. gspot runs Ruff and its
other Python tools on its own Python, so they work whatever Python version your project uses.

## Quotes

Ruff formats Python strings with double quotes. To keep single quotes, run `gspot set format.quotes single`, which applies
to every language.

## Modules from outside the project

List the modules that a host application provides in `python.externals`, as
[Modules that the host provides](/configure/import-rules/#modules-that-the-host-provides) shows. List extra source
folders in `python.import_folders`, and basedpyright and `structure/import-rules` then find the modules in them.

When the host application is outside the repository, add a `.pth` file that names the host folder to the `site-packages`
folder of `.venv`. Python and basedpyright read the folder paths in a `.pth` file, as they do for an editable install:

```shell title="example"
echo "<host-folder>" > .venv/lib/<python-folder>/site-packages/host.pth
```

`<host-folder>` is the absolute path of the host application, and `<python-folder>` is the Python folder of the
environment, such as `python3.12`.

## Unused code and long functions

At level `all`, `python/vulture` finds functions, classes, and attributes that no file of the scope uses, and code that
never runs. It cannot tell the public API of a library from unused code, so level `basic` does not run it. A framework
can call a definition by its name, which vulture does not see, so ignore the file that holds such a definition, with a
reason:

```shell
gspot ignore python/vulture --paths nodes.py --reason "ComfyUI calls the execute method of each node."
```

At level `all`, `python/function-size` allows each function 60 lines. To change the limit, set
`limits.python.max_function_lines` with a reason.

## Docstring style

pydoclint takes its docstring style from the first source that sets one, and otherwise uses the NumPy style:

1. A `[tool.pydoclint]` style in `pyproject.toml`.
2. The pydocstyle convention in the Ruff options of the project.
3. `python.docstring_convention`, when it equals `google` or `numpy`.
4. Google or NumPy sections that gspot finds in your docstrings.
