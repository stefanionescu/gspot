# Plain Language

All project-authored text must follow the governing principles and guidelines in ISO 24495-1:2023.
Apply this requirement to
README files, guides, Markdown, comments, docstrings, node help, tooltips, labels, errors, workflow
notes, examples, and generated text.

Write for the reader's task. Include the information they need, put it where they can find it,
explain it in familiar words, and make the next action clear. Use short, direct sentences and
explain technical terms when readers need them. Use the same name for the same thing. Follow
[DOCUMENTATION.md](DOCUMENTATION.md) for documentation casing, structure, and formatting. Preserve exact API identifiers and legal license text.

Describe current behavior. Do not include implementation history, private reasoning, acceptance
status, or temporary development notes in public content.

Evaluate the text throughout drafting from the intended reader's perspective. For substantive or
high-risk text, use feedback from representative readers when it is available. Record the limitation
when reader feedback is unavailable; do not claim that an automated check proves conformity. Do not
expand a small edit into a review of unrelated pages or rendered surfaces. Run formatting, spelling,
rendering, or other verification commands only when explicitly requested.
