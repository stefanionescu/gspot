# Documentation Content

A code example teaches one idea and uses the supported API. Include imports, setup, and any
surrounding context a reader needs. Label an incomplete fragment and say what it omits.
Keep volatile output out of examples unless the exact output is a public contract.

## Procedures and safety

State the starting directory and prerequisites before commands. Explain placeholders; never
present one as a value the reader can run unchanged. Separate output from commands, or comment
output where a copied block must remain runnable.

A destructive action names its scope, irreversible effect, backup, and recovery before the step.
Use secure defaults and least privilege. No example contains a credential or silently disables
certificate, permission, or access checks.

## Example choices

<!-- level: all -->

Keep authentication, retries, and advanced variants outside a minimal example unless correctness
needs them. Give alternatives complete procedures rather than interleaving platform steps.
State an expected result where success is unclear, and preserve required warnings outside tabs
or collapsed panels.

See [code samples](https://developers.google.com/style/code-samples)
and [procedures](https://developers.google.com/style/procedures).

## Links

Use maintained primary destinations for external contracts and relative paths for repository
content. Link text identifies the destination without needing its surrounding sentence. A public
procedure must not depend on an unstated account or permission to open a required page.

See [links](https://developers.google.com/style/cross-references).
