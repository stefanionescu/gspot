# Test Layout and Wiring

12 unresolved review records remain.

A read-only review wrote these findings on October 6, 2026, against commit `3e1445a2d`. The Existing column names an older record that covers the same problem.

The four suites, the flat harness, and the `config/` and `types/` mirrors exist. The structure under them is loose. These are the worst problems:

1. Bug: the fast-suite time limit depends on a regex that matches any `tools` or `packages` folder name in the test file's absolute path.
    - All 15 files under `tests/cli/tools/**` get the 15-minute tools-suite budget.
    - Any checkout under a folder with one of those names makes every suite "slow."
2. `tests/packages/binaries.test.ts` tests the per-OS archives. review/owner-decisions/001 deletes it, the `test:binary` task, and the archives.
3. The `tests` scope in `gspot.toml` selects 8 framework configurations for a workspace that has only `.ts` test files. This adds Astro, Svelte, React and Jest ESLint blocks for `tests/**`. Three `[[ignore]]` blocks then switch off what it turned on. Nothing requires it, because framework configurations are never selected automatically.
4. 32 tool tests repeat the same 10-line `beforeAll` block (budget plus shared repository). `[agent_rules]\nenabled = false\n` appears 150 times in 85 files. The quiet-init flag list is written out about 13 times. The harness owns none of these.
5. The mirror lags the moves. 55 single-user config/types files are not named after their test or do not sit beside it. `tests/types/generation/` is a second mirror next to `tests/types/{cli,tools}/generation/`. Five `lone_files_allowed` entries are stale.
6. `tests/tools` sorts tests two ways. `configurations/` is sorted by configuration. `checks/`, `generation/` and `execution/` are sorted by source owner. One configuration's tests sit in up to four folders (Docker: 3, secrets: 3, Vale: 3).
7. About 25 `tests/cli` files sit away from the source they test: snapshot, parse-output, read-policy, docs, automation, push, revisions, nginx, naming split, and others.
8. Test-only registry fakes live in `scripts/registry/` and get a second import alias. The suite time limits are defined in four places.
