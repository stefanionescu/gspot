# READMEs, Guides, Reference Generation, and the Docs Site

3 unresolved review records remain.

A read-only review wrote these findings on October 6, 2026, against commit `3e1445a2d`. The Existing column names an older record that covers the same problem.

The site structure now matches the target in `findings/images/docs.png`. The pages around it have these problems, worst first:

1. Release-status text ships in the npm READMEs and on a site that deploys only after a release. The first publish will tell npm readers that gspot "is not published on npm yet."
2. Every "Edit page" link on the deployed site is dead: it targets `/edit/<commit SHA>/`. The `add` and `remove` command pages link to source files that do not exist.
3. The templates guide shows the wrong template name. It does not say which customizations travel to the other repository. It does not say that private GitHub templates fail. That is the export-and-reuse flow the owner wants.
4. `remove.md` and `dependency-licenses.md` describe old selection behavior. `gspot remove` now records a lasting manual choice, and `licenses` is selected automatically.
5. The site has its own link checker (`docs/links.ts`), but gspot already ships a `site` configuration that checks links, fragments, unused CSS, and unused assets. External links in the guides are checked by nothing.
6. The published JSON Schema is a second validator. About 700 lines of test data keep it in agreement with the runtime validator. Its URL has no version, and the site has never been deployed (it returned 404 on 2026-10-06).
7. Copies: the install text exists in 4 places, the recorded example in 3 hand copies, and the level wording in 4 differing versions. Version `0.1.0` is hard-coded in 13 places.
8. Site code repeats Starlight features: a theme picker, a second mobile theme picker, a tab switcher, a Hero override, and a 3-file route middleware for one 404 canonical tag.
