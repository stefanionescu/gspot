# Tests in `tests/cli`

125 unresolved review records remain. IDs and verification evidence are retained in the JSON checklist.

A read-only review wrote these findings on October 6, 2026, against commit `3e1445a2d`. The Existing column names an older record that covers the same problem.

1. Tests keep removed features alive. `commands/local-override.test.ts` tests gspot.local.toml, which D-173 removed. Sixteen docs rows, four policy tests and one parser row assert that removed setting names stay refused, though the strict schema already refuses every unknown key.
2. Tests copy shipped configuration data and pin it: 141 Ruff rule codes, the lefthook and mise file lists, tool versions, tool counts, naming ceilings, Vale styles, install hints. Every configuration bump breaks them with no behavior change.
3. One block runs every finding case (`describe` + `beforeAll` + budget + loop) and is pasted into 9 CLI files, with skip branches no CLI case can reach.
4. Many tests start child processes only to pass stdin or because the harness lacks one option: 15 in `push/revisions.test.ts`, 8 call sites (several in loops) in `init/javascript-detection.test.ts`, 10 `node` children in `serialization/documents.test.ts`. `checks/general/gspot.test.ts` runs real package-manager and `uv lock` resolution in the one-minute suite.
5. Time budgets and platform rules have many special cases. Four places set the suite timeout, and seven places pass their own step limits. Ten tests in seven files skip on a platform although they only stub tools. See "Carve-outs."
6. The same behavior is tested two or three times in different folders. Examples: Git source reads, policy refusals, CI detection, dry-run diffs, and parser visitors that are source clones.
7. Release tests and the mise pin still cover per-OS standalone archives, which the npm-only decision dropped.
8. The template feature is tested end to end. `tests/tools/commands/template.test.ts:55-90` runs export and then init from the template. The CLI suite covers export (`policy/template.test.ts`) and `init --from` (`commands/init/templates.test.ts`, `commands/configuration-overrides.test.ts:126-136`). One test is missing: none compares the policy that `init --from` writes with the source policy (review/commands-templates/014).
9. Many findings repeat open records in `findings/areas/integration-tests.md` and `findings/slices/tests-integration-*.md`. They are left out below unless this review adds sites or a new angle.
