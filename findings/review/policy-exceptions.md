# This Repository's Own gspot Policy: Entries and Customizations

1 unresolved review record remains.

A read-only review wrote these findings on October 6, 2026, against commit `3e1445a2d`. The Existing column names an older record that covers the same problem.

Checked against HEAD 3e1445a2d on 2026-10-06. gspot.toml has 1,006 lines. It holds 12 `[[ignore]]` tables, 7 tool excludes (31 docs paths alone), 5 CodeQL ignores, 60 structure path entries, 34 fixed key names, 4 allowed names and 156 `prose.vocabulary` words. Decision D-135 permitted policy entries only for names. Most of the rest hides bloat or is dead.

1. The `tests` scope selects 9 framework configurations (`gspot.toml:85-97`). The 877 test files are all `.ts`, with no JSX, Svelte, Astro, or Vue code.
    - This one list causes 3 of the 5 `tests/**` ignores. It also puts 465 lines of NestJS, React, Next.js, Svelte, and Vitest agent rules into `AGENTS.md`.
    - The likely real reason is that `pin:eslint-presets` reads plugins from `.gspot` (`CONTRIBUTING.md:46-47`), and that task is already broken for vue and tanstack-query.
2. Dead entries survive because `structure/stale-allowlists` only checks that a path exists. It never checks that an entry still suppresses anything.
    - Dead today: 7 of 34 fixed key names, 5 of 28 lone-file paths, the html `prefix_collisions_allowed` entry, docs path `bash`, `roles.runtime` `src/**`, and two registry globs.
    - Also dead today: 2 of 3 `script_files` entries and 57 of 156 `prose.vocabulary` words.
3. The modules are not one-way. Both the allowed graph and the real import graph have two cycles. `config/eslint.ts` and `config/formatting.ts` belong to no module, so the boundary rule never checks imports into them. The `tool-output` module duplicates `parsers`, and three permissions are never used.
4. `tools.eslint.node_version = ">=24.2.0"` overrides the ESLint plugin's own `engines.node >=22`. The plugin is linted against the wrong Node version.
5. `naming.banned` blocks `render` and `resolve` but not `rendered` or `resolved`. Code goes around it: `renderedFragments`, `resolvedAttributes`, `synced`.
6. 16 of the 19 root `configurations` and all 4 scope `javascript` entries are selected automatically anyway. They are noise.
7. Of the 31 `docs.exclude` paths, 17 can go: delete `CONTRIBUTING.md` (`review/owner-decisions/007`), make two small `docs/stale-paths` fixes, and delete `bash`.
8. `tools.lychee.exclude` switches off external link checks for the whole manual, not only its root-relative links.
9. Code holds 16 real suppressions. Seven of them work around a rule instead of fixing the code.
