41 unresolved review records remain.

A read-only review wrote these findings on October 6, 2026, against commit `3e1445a2d`. The Existing column names an older record that covers the same problem.

HEAD 3e1445a2d, 2026-10-06. 577 CLI source files (2,756 internal imports: 1,895 value, 861 type-only), 53 plugin files.

1. `gspot.toml` module rules allow six two-way import pairs, put eight files in two modules and two config files in none, so the middle four modules are one tangle nothing checks.
2. The knot has four causes: `engines.ts` imports generation and lifecycle for `gspot/drift`; `tools/pins.ts` is manifest math that 19 files in 6 modules import; `Session` bundles tool state; generation and lifecycle read `execution/planning/`.
3. The owner's three files:
    - `commands/policy-edit.ts` is the shared "save gspot.toml, then apply" step, not a command.
    - `tools/installation.ts` is an 8-line pin decision that installs nothing.
    - `tools/installed-files.ts` is the read half of `lifecycle/ownership/installations.ts`.
4. Overloaded words: "output" (13 `output.ts` files, 4 meanings), "configuration" (the selectable unit, a tool file, `config/`), "rules" (two exported `RuleSettings` types), "install" (12 file names).
5. Mirrors show misplaced files: `checks/general/vale.ts` (mirrors say prose), `config/lifecycle/drift.ts` (used by a check), `config/parsers/command.ts` (not used by `parsers/command.ts`), `parsers/python/tools.ts` (the Python half of `tools/npm/`), `parsers/schema/agent-rules.ts` (a policy schema).
6. Forwarders and tiny single-importer files to merge: `parsers/document.ts`, `lifecycle/rule-diff.ts`, `tools/locks.ts`, `policy/settings/ignores.ts`, `parsers/tsconfig.ts` with `repository/tsconfig.ts`, and `parsers/schema/rules.ts` (alive only through a `no-trivial-files` suppression).
7. Carve-outs (own section, 17 groups):
    - `execution/planning/requirements.ts` names 8 tools and checks inline.
    - 11 `run_with === 'mise'` branches.
    - Vale has its own install, copy, and removal paths.
    - Installs ignore `tool_timeout_seconds` beside four fixed deadlines.
    - 11 output-truncation limits.
    - 9 OS branches outside `platform/`.
8. No value-level import cycles and no dead files. Seven type-level cycles, all through config/types. The only roots are `main.ts`, `tools/eslint/worker.ts`, and two ambient `.d.ts` files.
9. `findings/images/source.png` and `main/127` still say to delete `config/` and `types/` and create `kits/`, both overruled on 2026-10-04 and 2026-10-05.
