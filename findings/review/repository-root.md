# Repository Root, Scripts, Workflows, and Package Wiring

7 unresolved review records remain.

A read-only review wrote these findings on October 6, 2026, against commit `3e1445a2d`. The Existing column names an older record that covers the same problem.

1. The per-OS binaries are back. The owner dropped them on 2026-09-29, and commit 6d4219ae5 removed them on 2026-09-30. Commit 4ce293ae8 (2026-10-05, "complete repository ownership and test layout") brought the whole pipeline back:
    - A 5-target CI matrix.
    - Archives attached to the release.
    - A mise pin on `github:stefanionescu/gspot` that every consumer who picks mise gets.

    The owner decided on October 6, 2026 to delete them for good (review/owner-decisions/001).

2. `mise run setup` runs `scripts/build.ts`, which rewrites two tracked CLI data files. CI and the release run setup and never diff the result, so CI tests regenerated data and the release publishes it. Neither is the committed data.
3. The `test` job installs about 38 tools, CodeQL included, on Linux, macOS, and Windows. The suite it runs uses no real tools.
4. `install:checks` always passes `--refresh-locks`. CI re-resolves `.gspot/bun.lock` and `.gspot/uv.lock` on every run, never installs the committed lockfiles, and never diffs them.
5. CI type-checks the same four projects twice: `check:types`, then `typescript/tsc` inside `gspot check`. The root `tsconfig.json` repeats the 7 flags that CONTRIBUTING says only the generated file holds.
6. The light setup sequence (mise-action, `mise install bun node`, `bun install`) is written out 7 times across 4 workflows. The mise version is pinned 9 times.
7. `gspot.toml` was meant to get 60 lines shorter. It grew from 685 lines (audit, fb427a863) to 1,006. The `tests` scope pulls in 8 framework configurations for a folder of plain `.ts` files.
8. `scripts/package.ts` and `scripts/registry/plugin.ts` are two copies of one registry runner. Root `scripts/` and `packages/cli/scripts/` import each other.
9. Carve-outs:
    - Test time limits come from five places (per test, suite, command, step, and job), with 11 different job limits.
    - Only some jobs get `MISE_ENV`, `native-tests`, Defender off, and `fetch-depth: 0`.
    - A full Verdaccio proxy, which alone causes 4 of the 16 overrides, serves two local packages; the owner deleted it (review/owner-decisions/005).

    The "Carve-outs" section proposes one setting for each.

10. `docs/links.ts` is an 85-line link checker. The repository already pins and runs lychee. `docs/astro.config.ts:54` points every production "Edit page" link at a commit SHA, and GitHub cannot edit a file there.

**Uniform replacement:** one per-test limit and one job limit (review/carve-outs/001).

1. **Per test:** one number for every suite, set in one place.
    - The preload applies it with `setDefaultTimeout` from `bun:test` for every suite, including the database test, and no runner, task, or workflow passes `--timeout`.
    - One measured run picks the number.
    - No literal timeout stays in mise.toml or workflows, and the harness matches no path (review/carve-outs/001).
2. **Per job:** one `timeout-minutes: 60` on every job, with enough tools shards that each fits.

Delete `SOURCE_SUITE_TIMEOUT_MS`, `PACKAGE_SUITE_TIMEOUT_MS`, `SOURCE_COMMAND_TIMEOUT_MS`, and `scripts/deadline.ts`. The archive, plugin-publish, and Verdaccio step constants go with review/owner-decisions/001 and 005. `DOWNLOAD_TIMEOUT_MS` stays as the one limit for the grammar download (review/repository-root/016).
