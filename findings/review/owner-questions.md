## Questions that were open

### Release and install

**Q1: Keep the per-OS standalone archives that commit 4ce293ae8 added?**
Today the release builds five archives (`scripts/binaries.ts`, `scripts/config/release.ts:2-8`, CI job `binary` at
`.github/workflows/ci.yml:107`) and uploads them to the GitHub release (`release.yml:126`). mise installs them
through `github:stefanionescu/gspot`. On September 29 you chose plain JavaScript on npm and no per-OS binaries.

Options: a) keep the archives as GitHub release assets for mise only, with no npm platform packages; b) remove
them and ship npm only, as decided.
Recommendation: a), because it is the only path that lets a Python or Swift team run gspot without Node.js.
Origin: `FINDINGS.md D1`, `areas/developer-experience.md Q1`. If you choose b), `areas/developer-experience.md Q6`
(install channel) reopens too.

**Q2: Keep the Cloudflare deploy of gspot.dev that commit 4ce293ae8 added?**
Today `docs.yml` deploys the site to Cloudflare Workers after each release (`docs/wrangler.jsonc`, `CONTRIBUTING.md:266-273`).
The repository has no environments and no secrets, so the deploy cannot run. gspot.dev answers with a page, and
`https://gspot.dev/schema/gspot.schema.json` returns 404. Every generated `gspot.toml` starts with that schema URL
(`packages/cli/src/config/commands/init.ts:20-22`). On October 1 you said to delete the deploy plumbing.

Options: a) keep the Cloudflare deploy, and add the `documentation` environment and the two Cloudflare secrets;
b) delete the deploy job and the `#:schema` line.
Recommendation: a), because docs links and every generated `gspot.toml` point at gspot.dev.
Origin: `FINDINGS.md D15`, `areas/repository.md Q2`, `areas/docs.md Q3`.

### Checks and configurations

**Q3: Let TruffleHog scan a commit range itself, instead of gspot listing each pushed commit?**
Today gspot lists the commits and feeds their blobs to TruffleHog (`packages/cli/src/checks/general/secrets.ts:37-46,232-260`).
Options: a) keep the gspot commit list; b) use TruffleHog's own Git source with `base..HEAD`.
Recommendation: a), because one push can update several refs, and `base..HEAD` covers only the current branch.
Origin: `areas/checks.md Q5`.

**Q4: Replace the `i18n/locales` check that gspot implements with i18n-check?**
Today gspot runs its own engine (`packages/cli/src/checks/library/i18n.ts`).
Options: a) keep the engine; b) replace it.
Recommendation: a), until one run shows that i18n-check reads the message files of all five detected libraries
(next-intl, i18next, react-i18next, react-intl, Lingui).
Origin: `areas/checks.md Q6`.

**Q5: Make `[[ignore]]` the only way to skip paths or accept findings?**
Today both forms exist. Examples: `tools.semgrep.exclude`, `tools.knip.exclude`, `tools.codeql.ignore`,
`tools.trivy.ignore`, and `docs.exclude`, next to `[[ignore]]`. Open Source Vulnerabilities (OSV) already moved
to `[[ignore]]` (`gspot.toml:544-554`).

Options: a) yes, delete the per-tool lists; b) no, keep both.
Recommendation: a), because one job needs one way, and the OSV entries show that `[[ignore]]` works.
Origin: `areas/kits.md Q2`.

**Q6: Which rule names checks?**
Today checks that run a tool carry the tool name (`python/ruff`), and checks gspot implements carry a purpose name
(`python/file-lines`).
Options: a) keep this rule and write it down; b) purpose names everywhere; c) tool names everywhere.
Recommendation: a), because the tool name tells users whose docs and suppression syntax apply.
Origin: `areas/kits.md Q5`.

**Q7: Keep `--remove` on `set` and `ignore`, next to the `remove` command?**
Today `remove` removes a configuration, `set --remove` removes list items (`commands/set.ts:231`), and
`ignore --remove` deletes ignore entries (`commands/ignore.ts:167`).
Options: a) keep; b) rename the two flags.
Recommendation: a), because each meaning stays inside its command, and you confirmed the command set on October 6.
Origin: `areas/kits.md Q6`.

**Q8: Delete `.whitelizard` from the ESLint takeover list?**

Recommendation: a), because no tool the audit or this check knows reads `.whitelizard`.
Origin: `areas/kits.md Q7`.

**Q9: Keep the two NestJS rules that forbid injecting a repository into a controller in the shipped configuration?

Today all three ship (`configurations/framework/nestjs/manifest.toml:36-45`,
`configurations/framework/react-native/manifest.toml:45-47`).
