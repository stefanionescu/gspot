# Kits: Frameworks, Libraries, Platforms, Tools, and Postgres

The review read all 68 non-rule files in the 29 kits of this slice: manifests, ESLint fragments and imports, Semgrep files, and tool templates. 49 files have new findings.

The biggest problems: one shipped Semgrep rule is invalid and breaks the whole Semgrep check for FastAPI projects. The central ESLint level table silently turns off rules that kit fragments switch on. Several checks and rules assume one tool or layout (next-intl messages, OpenNext type files, Supabase-style migration names, Expo's text component). Some rules report documented, correct code: Supabase's own CORS helper, React Hook Form checkboxes, `Map.delete`, and the tRPC adapter route. Several summaries and descriptions claim things the kit does not do.

How the review checked: it ran `semgrep --validate` and sample scans with the Semgrep in `.gspot/.venv`, zizmor 1.30.1, and Trivy 0.69.3. It also ran `npm view` on every npm pin (all 28 exist) and read the presets inside the pinned plugin tarballs.
