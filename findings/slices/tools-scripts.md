# Tool Installation and the Package Build

The review read 19 files: the 14 under `packages/cli/src/tools`, the three build scripts, `package.json`, and `tsconfig.json`. 17 of them have new findings. Four patterns repeat:

- Names and doc comments describe intent, not behavior: a function called `prepare…` only checks versions, `readVersion` parses, and docs say "native bounds" or "immutable inputs."
- Several parameters and constants never change a result.
- The npm and Python halves copy each other's literals and return types.
- Small rules are written several times: the Yarn Berry test, Windows executable names, the virtual environment's bin folder, and "is the prose kit selected."

**Corrections to the first pass:**

- Execution row on `tools/inspect.ts:44`, `commands.ts:79,121`, `identity.ts:85`: "twice as `<manager> --version` for the same manager in one install" is wrong for `gspot install` in a clone. `packageTool` returns the manager recorded in `.gspot/package.json` without running it (`identity.ts:82-84`). The command runs twice only on a first init or apply, or after the detected manager changes.
- Execution row on `tools/inspect.ts:182-190` `locateTool`: "reads `gspot.toml` and every kit manifest again" overstates it. `kitManifests()` is cached per process (`kits/manifests.ts:135`), so only `gspot.toml` is read again. Deleting `locateTool` also means rewriting two integration tests that call it directly (`tests/integration/cli/tools/inspect/placement.test.ts:111`, `installations.test.ts:206`).
- Repository row on `packages/cli/package.json:35-37` `sideEffects`: commit 53c944a0 added the field to satisfy `package-json/require-sideEffects`, which is on at level `all`. Deleting it fails lint unless the same change turns that rule off for this file, as `gspot.toml` already does for `package-json/require-exports`.
- Same `sideEffects` row: "This package has only a `bin`" is also false. The docs site imports its source through the workspace (`docs/src/content/reference/collection.ts:6-8`).
- Repository row on `packages/cli/package.json:41-44` `imports`: the docs site builds CLI source with Astro's Vite. It imports `@gspothq/cli/src/commands/program.ts`, `kits/listing.ts`, `kits/manifests.ts`, `policy/json-schema.ts`, and others, and their `#cli/*` and `#cli-package` imports reach `tools/packages/environment.ts`.
