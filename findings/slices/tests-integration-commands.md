# Tests: Command, Policy, Platform, and Tools Integration Tests

The review read all 43 files in full: 27 in `commands`, 3 in `policy`, 5 in `platform`, 4 in `tools`, and the four top-level files. 40 have new findings. Paths below are relative to `tests/integration/`. The main patterns are these:

- A few assertions cannot fail because the check or the call never reaches the case they claim.
- Many refusals assert only exit 2, which gspot gives for every error.
- Tests use local copies of harness helpers (`git().stdout`, `expect.stringContaining`, `isWindows`, a hand-built source path).
- The hidden `if (onPosix) test(...)` skip and the hand-written `describe >` prefix in test names repeat across files.
