# Tests: Generation Integration Tests

The review read all 28 files in `tests/integration/cli/generation` in full: 20 at the top level, 5 in `plugin-levels`, and 3 in `serialization`. 26 have new findings. Paths below are relative to `tests/integration/`. The main patterns are these:

- Some assertions cannot fail: a rule the policy never configures, a "future" file that exists before generation, and byte checks after calls that only read.
- Four places rebuild what `generatedEslint` or `emitted` already do, one of them with the Windows link the harness avoids.
- Several test names say "enforces," "apply," "kit," or "after inventory" where the body asserts something else.
- Files sit in folders that do not match their subject (`plugin-levels`, `serialization`, `vale-packages`).
