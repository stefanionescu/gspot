# Execution, Parsers, and Output

The review read all 28 files in full: 20 in `execution/`, 6 in `parsers/`, and 2 in `output/`. 26 of them have new findings. The main patterns:

- Dead fields and dead logic in planning and reporting: `projectWide`, `ReportInput.active`, `seenRepoChecks`, and a branch in `unrunnableResult`.
- One likely planning bug: `allOwned` brings back paths the user excluded.
- Comments that are stale or wrong, such as "embedded" in the parser headers and the inverted doc of `isRepositoryPolicy`.
- Names that hide what the code does: `planCorrections`, `checkExecution`, `isWholeCheck` next to `isWhole`, and three words for "fix."
- User messages that say "staged content" or "the index" during push runs.
- `QUIET_HIDES`, which hides passed checks with or without `--quiet`.

All paths are under `packages/cli/src/` unless they start with `tests/`. The behavior claims come from reading the code. The review ran nothing except `git grep`.
