# Tests: Harness, Config, Types, and Package Tests

All 55 files were read in full: 41 in `tests/harness`, 2 in `tests/config`, 4 in `tests/types`, 5 in `tests/packages`, and `tests/package.json`, `bunfig.toml`, and `tsconfig.json`. 44 files have at least one new finding, listed in 52 rows. The main patterns are these:

- Most builder functions are named as nouns or end in `Of`, and computed module values are named like literal constants.
- Doc comments and parameter names still say "configuration" for a kit, "guides" for agent rules, and "correction" for a fixer.
- Helpers repeat what the product owns: `gspot remove`, the Python module reader, the `Level` and `SpawnResult` types, and part of `apply`.
- The same text is written in several places: the npmrc, the `[rules]` table, and the planted-repository shape.
- The package tests repeat harness helpers, assert values that cannot fail, and give each test the same limit as one of its commands.
