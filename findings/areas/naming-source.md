# Names in the code

This area is the names a contributor reads in the code: file and folder names, exported functions, types and
constants, parameters, and object fields in `packages/cli/src/`, `packages/eslint-plugin/src/`, and `scripts/`. Today
125 files are named `public.ts` or `contracts.ts`, many identifiers say something false, and some concepts have up to
nine names. The target: one name for each concept, as `glossary.md` fixes it, and the final file and identifier
names in the two rename tables below. Paths are relative to `packages/cli/src/` unless they start with `packages/`,
`scripts/`, `docs/`, or `tests/`.

## Findings

### NMS-006: "native" has at least nine meanings

- Where: 452 lines in 181 files; 22 compound identifiers with 60 uses (`nativeSegments` 9, `nativeDiagnostic` 8,
  `NativeOverride` 4, `nativeFix` 3, `nativeSetting` 3, `NativeIgnore` 3, `nativePath` 3); the string `'native'` 13
  times
- Kind: rename
- Problem: The word means a different thing in each place: (1) the tool's own behavior ("native findings"); (2) gspot's
  own fix (`nativeFix`), the opposite of meaning 1; (3) the path rules of this operating system (`PathFormat = 'portable' | 'native'`, `types/platform/root.ts:8`); (4) a hand-written setting schema (`nativeSetting`, and the
  manifest value `items = "native"`); (5) generated schemas (folder `policy/schema/native/`); (6) a Prettier or
  EditorConfig override (`NativeOverride`); (7) a tool's own ignore list (`NativeIgnore`); (8) setting help text
  (`nativeDiagnostic`); (9) `PATH` with pinned tools (`nativePath` in `scripts/plugin.ts`). It is also filler in doc
  comments ("native trees", "native captures"). And "native" is the word for the per-OS binaries the owner banned.
- Fix: Delete "native" from doc comments; say what is meant or nothing. Rename the identifiers as Rename table B
  shows: `builtInFix`, `PathFormat` value `'system'`, `ExtraOverride`, `ToolIgnore` and `toolIgnore`,
  `settingHelp`, `tomlAssignment` and `tomlHeader`. `nativeSetting`, `policy/schema/native/`, and the manifest field
  `items` go with the setting-schema generator (POL-001; a setting declaration has no `items` field), and
  `nativePath` goes with `scripts/plugin.ts` (SCR-003).
- Size: medium

### NMS-009: The package manager is called "package installer", and npm, Bun, pnpm, and Yarn have four names

  `types/planning.ts:17`, `types/tools/python.ts:9`, `generation/public.ts`, `tools/python/public.ts`,

  `config/parsers/dependency-files.ts`; the session method `npmClient()`; `uvPath` and `uvPin` for uv. `LOCKFILES`

### NMS-016: `get` hides process runs and file reads

- Where: 85 names that start with `get` (297 uses), for example in `repository/revisions/public.ts`,
  `repository/contracts.ts`, `parsers/packages/public.ts`, and `policy/document/contracts.ts`
- Kind: rename
- Problem: Many `get*` functions run Git or another process, read files, or download text, while `get` reads like a
  cheap field access: nine `get*` functions in `repository/revisions/public.ts` run Git (`getStaged`, `getChanged`,
  `getBlobs`, `getPushBase`, `getMergeBase`, `getDefaultRef`, `getHeadEntries`, `getRemoteHeads`, `getEntries`);
  `getSubmodulePaths`, `getProjectDependencies`, `getTsconfig`, `getOwnership`, `getScriptIndex`, `getLintJobs`,
  `getTooling`, and `getHooks` run Git or read files; `getTemplate` and `getRemoteText` download text. Other vague
  words are rare: `handle`, `process`, `ensure`, `perform`, and `manage` never start a name, and the `Helper` and
  `Util` suffixes do not occur.
- Fix: Use a verb that names the cost: `read*` for files and Git objects, `list*` for listings, `run*` for processes,
  `download*` for the network; a pure lookup is a plain noun (`submodulePaths`, `projectDependencies`). Rename table B
  gives every final name.
- Size: medium

### NMS-019: Vague words that the naming ban covers appear in gspot's own comments and messages

- Where: doc comments and messages across the CLI and the plugin
- Kind: rewrite-text
- Problem: This repository bans these words in names (`naming.banned` in `gspot.toml`, `naming.banned_words` in the
  target). The ban covers identifiers and
  file and folder names only, so comments and messages break no check, but they are still vague:
    - "scoped": 31 lines (`@param planned the scoped check`; the message "The prose configuration has no scoped Vale
      tool file.").

    - "catalog": 3 lines of gspot's own text (`config/generation/eslint.ts:6`, `generation/eslint/public.ts:231,245`:
      "the catalog must use eslint@..."). Apple's "asset catalog" and Knip's "catalog" are tool words and stay.

    - "bind" and "bindings": doc comments such as "Bind rule data and preset reads…"
      (`generation/eslint/configuration.ts:133`) and "Bind source bytes…" (`platform/root/public.ts:309`).

    - "load": 8 lines (the `readPolicy` doc "Loads"); "fetched": the message "A template is fetched over https".
    - The "resolve" family: about 170 lines; part are tool words (TypeScript module resolution, npm's `resolved`
      field), the rest gspot text such as "the resolved scopes".

    - Messages: "Vale package sync was canceled." and "Vale package sync exceeded its tool deadline."
      (`lifecycle/install/contracts.ts:140-141`), "Cannot load the repository registry settings"
      (`tools/npm/contracts.ts:123`), "Install it before resolving its lockfile" (`tools/npm/public.ts:92`), "Cannot
      resolve pushed object" (`repository/revisions/contracts.ts:56,74,123`), "Git attribute resolution failed"
      (`repository/public.ts:234`), "The runtime cannot resolve this existing filesystem path"
      (`platform/root/reads.ts:169`), and the setting summary "The runtime per scoped file selector"
      (`configurations/language/javascript/manifest.toml:544`).

- Fix: Rewrite with plain words. Doc comments: "scoped check" becomes "check for one scope", "resolved scopes" becomes
  "selected scopes", "Bind X to Y" becomes "Give X to Y", "Loads" becomes "Reads". Messages: "Vale package install was
  canceled", "ran longer than tool_timeout_seconds" (EXG-030), "Cannot read the registry settings", "before it creates

  per-scope Vale file any more, so its message goes.
