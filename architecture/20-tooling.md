# Tooling Research

The full tool coverage, after reading MegaLinter's 136 linters and the four reference repositories.
Tools already covered in [13-language-presets/](13-language-presets/) are listed only where this
research changes the choice.

Every entry states what it adds that nothing else in the set provides. A tool with no distinct
answer to that question does not enter the distribution.

## One tool per job

The rule that governs every row below: **a second tool enters only when it does something the first
cannot.** Two tools for one job means two configurations that must agree, two finding formats for
one defect, and two exception lists. The reference set rejects Lizard on exactly this ground and
then runs four vulnerability scanners. The rule applies to gspot without exception.

Applied, the rule cuts these from earlier drafts of this design:

Thirty cuts. What remains is one tool per kind per language, and the matrix below is the whole
of it.

## Rejected, with the reason

| Tool                                                                    | Why not                                                                                                                                                                                                                                                                                                                                                       |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Biome**                                                               | Fast and coherent, and it cannot host the eighteen structural rules, the sonarjs cognitive metric, the boundaries zones or type-aware rules. Its `useNamingConvention` is genuinely good and does not reach the banned-term policy. Revisit when custom rules land.                                                                                           |
| **oxlint**                                                              | Same dual-engine objection as D-04. Revisit as an opt-in `--fast` pre-pass that runs a strict subset.                                                                                                                                                                                                                                                         |
| **dprint**                                                              | A faster Prettier with a plugin model, and Prettier is what four reference repositories configure. Switching costs a whole-tree reformat for a speed gain.                                                                                                                                                                                                    |
| **checkov**, **kics**, **tflint**, **terragrunt**                       | Infrastructure as code. No reference repository has Terraform. The preset setting exists and is empty.                                                                                                                                                                                                                                                             |
| **dependency-cruiser**                                                  | D-08 stands. Its unique feature, orphan-module detection, is covered by `knip`.                                                                                                                                                                                                                                                                               |
| **madge**                                                               | `import-x/no-cycle` covers cycles. `yap-landing` uses madge and would drop it.                                                                                                                                                                                                                                                                                |
| **lizard**                                                              | `yap-landing` wires it correctly, with a validated baseline. It is still dropped: `sonarjs/cognitive-complexity` covers JavaScript and TypeScript, Ruff `C901` covers Python, and SwiftLint covers Swift, so Lizard would be a fourth complexity metric that disagrees with the other three. Its **baseline mechanism** is adopted wholesale as the baseline. |
| **qlty**, **trunk**, **pre-commit**, **MegaLinter** as the orchestrator | D-01. gspot emits a `pre-commit` hook definition and a MegaLinter-compatible report, and does not run inside either.                                                                                                                                                                                                                                          |
| **license-checker** 25.0.1                                              | Unmaintained. `license-checker-rseidelsohn` is the fork, and two reference repositories already disagree about which to use.                                                                                                                                                                                                                                  |
| **reuse**, **license-eye**, **addlicense**                              | Per-file licence headers. Worth having for a published repository and out of scope until gspot itself is published. D-42.                                                                                                                                                                                                                                     |
| **`ossf/scorecard`**                                                    | Repository security posture. A CI report, not a gate, and its findings are mostly about GitHub settings rather than code.                                                                                                                                                                                                                                     |
| **danger**                                                              | Pull-request policy automation. A different product.                                                                                                                                                                                                                                                                                                          |
| **Semgrep** against **opengrep**                                        | Both adopted: the same rule format, so the preset's rules run under either, and the choice is the consumer's licence question.                                                                                                                                                                                                                                  |

## Kind gaps that no tool fills

Stated so the coverage check can report them honestly rather than implying coverage.

| Gap                                                 | Effect                                                                        | gspot response                                                                                 |
| --------------------------------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| **No SQL AST grammar in ast-grep**                  | SQL structural and naming rules cannot use a rule file                        | A sqlfluff rule plugin, a plugin, roughly 150 lines                                         |
| **No SQL SAST**                                     | Injection and privilege patterns in SQL are unchecked                         | Semgrep over the code that builds SQL; `platform:supabase` RLS and grant checks               |
| **No Bash complexity or dead-code tool**            | Two limits and one check have no provider for 204 files in the reference tree | Mechanism 4, roughly 280 lines total                                                           |
| **No Swift custom-rule AST API**                    | SwiftLint custom rules are regex only                                         | ast-grep Swift grammar for anything a regex cannot express, plus Semgrep, which supports Swift |
| **No prose linting inside string literals**         | Prompt text, error text and log text are invisible to Vale                    | Declared uncovered; ESLint and Ruff selectors own error and log shape. D-17.                   |
| **No Dockerfile structural or naming rules**        | hadolint covers style only                                                    | Accepted, and the required kinds says so                                                              |
| **No Ruff plugin system**                           | Python needs a second linter for banned terms                                 | pylint, complement-only                                                                        |
| **No tool reads `project.pbxproj` for correctness** | The Xcode project is unchecked                                                | Generate it with xcodegen, or parse it, original code                                            |
