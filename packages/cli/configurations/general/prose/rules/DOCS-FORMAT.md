# Documentation Format

Use the renderer's supported Markdown. Keep routine pages free of custom layout HTML or CSS.
Platform-owned components need useful text when the secondary renderer cannot show them.
The formatter and Markdown tools own mechanical layout.

## Meaning and structure

<!-- level: all -->

Give a page a title that names its task or subject. Explain the purpose before its sections.
Choose a paragraph, list, or table by what the reader needs to compare, not visual decoration.
A table compares multiple attributes; a list presents parallel actions or facts.

Use inline code for exact commands, values, fields, and identifiers. Bold names an interface
control; it does not replace a heading. A blockquote holds attributed source text, not an alert
or ordinary paragraph. Keep required instructions outside collapsed panels.

Delete obsolete content instead of hiding it in comments. Author comments explain maintenance
constraints. Keep private discussions and product history out of comments. A badge earns its space only when its
state affects the reader's decision and remains accurate.
